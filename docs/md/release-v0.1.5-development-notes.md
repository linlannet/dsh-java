# DeepSeek Harness Java v0.1.5 开发说明

> v0.1.5 的主线是插件能力完善与安全加固：对话中支持 `@插件` 显式提及，让模型优先使用指定插件的工具；插件命令接口增加访问控制；插件 ID、工具注册与提示词拼接补齐安全校验，修复目录识别误判和系统提示词中关于思考过程的错误要求。

## 2. 版本亮点

1. **`@插件` 提及**：控制台输入框支持 `@` 唤起插件候选列表，Agent 派发节点把提及转换为模型可见的优先级指令，便于对话中显式验证指定插件。
2. **插件接口访问控制**：新增 `PluginApiAuthFilter`，插件命令接口本机调用放行，远程调用必须携带 `X-Plugin-Api-Token`。
3. **插件 ID 安全校验**：注册时强制校验 `pluginId` 字符集，防止非法 ID 污染注册工具名与安装目录路径。
4. **工具注册幂等加固**：插件重复注册时复用已有工具名并释放新注册的资源，避免工具重复挂载。
5. **提示词注入防护**：插件工具描述写入系统提示词前清理换行与控制字符，且提示词中使用注册后的完整工具名，与 function calling schema 保持一致。
6. **目录识别修复**：路径真实存在且是目录时才改写为 `ls` 指令，避免把 `SELECT/SHOW/DESC` 等文本片段误当成目录路径。
7. **系统提示词修正**：不再要求模型输出思考过程标签，明确只输出最终回答。
8. **安装脚本加固**：`install-plugin.sh` 对安装请求字段做 JSON 转义，支持含特殊字符的路径与元数据。

## 3. 架构变化

v0.1.5 不改变六边形架构依赖方向，变更分布在四个层次，均属于既有能力的加固：

- **Trigger 层**新增插件命令接口鉴权过滤器 `PluginApiAuthFilter`；
- **Case 层**在 `AgentDispatchNode` 中解析 `@插件` 提及并生成优先级指令；
- **Domain 层**在 `PluginRegistryService` 增加 `pluginId` 字符集校验，在 `PluginToolBridgeService` 增加重复注册防御与提示词清洗；
- **App 层**修正系统提示词模板，并在 Web 控制台增加插件提及交互。

```text
Web Console（@插件提及补全）
        ↓
Trigger：PluginApiAuthFilter（命令接口访问控制）
        ↓
Case：AgentDispatchNode（@提及 → 模型优先级指令）
        ↓
Domain：PluginRegistryService（ID 校验）/ PluginToolBridgeService（注册幂等 + 提示词清洗）
```

## 4. @插件提及

### 4.1 控制台交互

输入框中输入 `@` 时，控制台从已安装插件中筛选 `ACTIVE` 状态的插件，按插件 ID 和显示名模糊匹配，展示最多 8 条候选：

| 能力 | 说明 |
| --- | --- |
| 唤起 | 在消息开头或空白后输入 `@`，弹出候选列表 |
| 匹配 | 按插件 ID / 显示名前缀模糊匹配，仅展示 ACTIVE 插件 |
| 选择 | `↑` / `↓` 移动高亮，`Enter` / `Tab` 确认，`Escape` 关闭 |
| 回填 | 选中后在输入框写入 `@<pluginId> `，光标落在其后 |

### 4.2 模型侧指令转换

`AgentDispatchNode` 新增 `@插件` 提及解析：

- 匹配规则：`(?<=^|\s)@([A-Za-z0-9][A-Za-z0-9._-]*)`，与 `pluginId` 字符集保持一致；
- 识别到提及时，在消息末尾追加 `[插件提及]` 指令，要求模型优先在对应 `plugin__<插件ID>__<工具名>` 工具中选择，其他插件工具只有在被指定或确实更匹配时才使用；
- 邮件地址等 `someone@example.com` 形态不会被误判为插件提及。

这样可以在不切换插件启停状态的情况下，显式引导模型验证某个插件的工具链路。

## 5. 插件接口访问控制

新增 `PluginApiAuthFilter`（`@Order(10)`），作用于 `/api/harness/plugins` 及其子路径：

| 场景 | 行为 |
| --- | --- |
| 只读请求 | `GET` / `HEAD` / `OPTIONS` 直接放行 |
| 本机调用 | `127.0.0.1` / `::1` 回环地址放行 |
| 远程命令调用 | 必须携带 `X-Plugin-Api-Token` 头，且与 `harness.plugins.api-token` 配置一致 |
| 鉴权失败 | 返回 `401`，响应体 `{"code":"A0300","info":"plugin API token required","data":null}` |

配置项：

```yaml
harness:
  plugins:
    api-token: <your-token>   # 远程调用插件命令接口时必填
```

读接口继续开放便于控制台展示；安装、运行、启停、卸载、配置保存等命令接口在远程访问时必须携带 Token，避免暴露主机后插件被任意安装或停用。

## 6. 插件注册安全校验

`PluginRegistryService` 在安装登记时新增 `pluginId` 强制校验：

```text
[A-Za-z0-9][A-Za-z0-9._-]*
```

即必须以字母或数字开头，只能包含字母、数字、点、下划线和短横线。

原因：`pluginId` 会参与注册工具名（`plugin__<pluginId>__<toolName>`）和安装目录路径拼接，若允许空白、斜杠等字符，会破坏工具命名规则并带来路径穿越风险。非法 ID 在安装阶段直接抛出 `IllegalArgumentException`，不会写入登记表。

## 7. 工具桥接加固

### 7.1 重复注册幂等

`PluginToolBridgeService` 注册插件工具时改为 `putIfAbsent` 语义：

- 插件首次注册：登记工具名、释放器和提示词区段；
- 插件重复注册：执行本次注册产生的所有 disposer，返回已有的工具名列表，不再覆盖已有登记。

避免插件被重复 `run` 时工具被重复挂载、提示词区段被重复写入。

### 7.2 提示词与 Schema 一致

插件能力写入系统提示词时，使用注册后的完整工具名（`plugin__<pluginId>__<toolName>`），而不是插件声明的裸工具名。提示词中的名字与 function calling schema 中的名字保持一致，避免模型按未加前缀的名字调用失败。

### 7.3 提示词注入防护

插件贡献的工具描述在写入系统提示词前经过 `sanitizePromptText` 处理：换行、回车、制表符统一替换为空格并去除首尾空白，防止恶意或异常描述通过换行伪装成提示词结构注入系统提示词。

## 8. 目录识别修复

`AgentDispatchNode` 的目录类任务改写逻辑增加真实存在性校验：

- 命中目录关键词和绝对路径后，先通过 `Files.isDirectory()` 确认路径真实存在且是目录；
- 只有确认是目录才改写为 `ls -la` / `find` 指令；
- 校验异常一律按非目录处理，不做改写。

修复前像 `SELECT/SHOW/DESC` 这类文本片段会被误当成目录路径，导致用户消息被改写得面目全非。

## 9. 系统提示词修正

`AgentRunBeanConfig` 中的格式要求从「思考过程用 `<thead>` 包裹」修正为：

```text
不要在正文中输出内部推理过程或 <think> 之类的标签，只输出最终回答。
```

原写法既有标签拼写错误（`<thead>`），又与当前模型行为不匹配，会导致模型在回答正文中输出推理标签。

## 10. 安装脚本加固

`scripts/install-plugin.sh` 新增 `json_escape` 处理安装请求字段：

- 反斜杠、双引号转义；
- 多行内容逐行拼接为 `\n`；
- 行尾多余 `\n` 去除。

插件 ID、显示名、版本、JAR 路径和入口类名在拼入 JSON 请求体前统一转义，路径中包含空格或特殊字符时不再破坏请求格式。

## 12. 接口与配置速查

### 12.1 新增配置

| 配置 | 说明 |
| --- | --- |
| `harness.plugins.api-token` | 远程调用插件命令接口的访问 Token，为空时远程命令调用一律拒绝 |

### 12.2 接口变化

插件命令接口（`POST /api/harness/plugins/**`）新增鉴权要求：

```http
X-Plugin-Api-Token: <token>
```

只读接口（`GET /api/harness/plugins/**`）与本机调用不受影响，接口路径与请求结构无变化。

## 13. 兼容与升级

### 13.1 兼容性

- 插件 SDK 契约不变，插件继续只依赖 `dsh-java-types`；
- 工具命名规则 `plugin__<pluginId>__<toolName>` 不变；
- 既有合法 `pluginId` 全部满足新字符集要求；
- 本机调用插件接口行为不变。

### 13.2 升级注意

1. 需要远程管理插件时，先在配置中设置 `harness.plugins.api-token`，并在调用方携带 `X-Plugin-Api-Token`；
2. `install-plugin.sh` 在本机执行不受影响；用于远程主机部署时必须补充 Token 请求头；
3. 历史数据中存在非法字符 `pluginId` 的，建议卸载后按新规则重新安装。

## 14. 已知限制

| 事项 | 说明 |
| --- | --- |
| `@插件` 提及只做优先级引导 | 模型仍可能在工具缺失时回退到其他插件，非强制路由 |
| 提及候选仅展示 ACTIVE 插件 | DISABLED / FAILED 插件不出现在补全列表 |
| API Token 为单值配置 | 暂不支持多 Token、按插件粒度授权或 Token 轮换 |
| 目录识别依赖宿主文件系统 | 远程环境路径不会被识别为目录，不会触发改写 |

## 16. 结论

v0.1.5 没有新增插件机制的主干能力，而是把 v0.1.4 交付的插件链路从「可用」推进到「可信」：对话侧可以显式指定插件进行验证，接口侧命令操作有了访问控制，注册侧 ID、工具名和提示词拼接都补齐了安全边界。

后续优化建议：

1. 将 `@插件` 提及升级为强制路由，提及时锁定工具候选集；
2. 为插件命令接口补充操作审计日志；
3. 支持按插件粒度的访问授权和 Token 轮换；
4. 把提示词清洗能力沉淀为统一的 `Sanitizer`，覆盖插件提示词、事件文本等其他外部输入。
